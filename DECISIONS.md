- 2026-11-01 — Приложение остаётся в корне репозитория. — GitHub Pages раздаёт сайт из корня; перенос в папку сломает адрес в BotFather.
- 2026-11-01 — Порядок развития: стабилизация Telegram-версии → английский язык → оплата Telegram Stars → проверка спроса → мобильное приложение. — Сначала проверить, платят ли люди, потом тратить месяцы на App Store и Google Play.
- 2026-11-01 — Подключён автодеплой воркера через Cloudflare Workers Builds (ветка `main`, папка `worker`): код, привязки KV/D1 и `compatibility_date` берутся из `worker/wrangler.toml`, секреты и переменные остаются в панели (`keep_vars = true`). — Ручная вставка кода в панель расходилась с репозиторием; теперь воркер не правится вручную в панели, все изменения только через GitHub.
- 2026-11-01 — Метка `?v=` убрана из адреса приложения в BotFather и `APP_URL` (теперь `https://olegkiselar3105-ui.github.io/FinansePro/`). — Она вызывала двойной запуск из-за устаревшей копии страницы в кэше Telegram; обновления работают через проверку `IB_VER`.
- 2026-11-01 — Окна над клавиатурой (v136): пружина второго порядка вместо первого, окно не следует за клавиатурой при переходе между полями и под вложенным окном (категории), страница не перекладывается (`fitScroll`) пока открыто окно, затемнение держит высоту без клавиатуры. — Окно проваливалось и взлетало при смене поля, падало при открытии категорий, первый подъём стартовал рывком (до 46 px за кадр); поведение самой клавиатуры iOS (мигание между полями, закрытие при выборе категории) изменить нельзя, сглаживается только реакция приложения.
- 2026-11-01 — Вложенные окна (v137): окно под ними пристёгивается к экрану по верхнему краю и не принимает касания (`pointer-events:none`, `inert`), панель категорий выезжает после ухода клавиатуры; внизу экрана показывается номер сборки (`APP_VER · IB_VER`). — При закрытии клавиатуры Telegram меняет высоту webview: окно, привязанное к нижнему краю, на кадры смещалось, панель категорий появлялась выше нужного и «проседала», а касания проходили в окно под ней. Номер сборки нужен, чтобы по скриншоту было видно, обновился ли Telegram (он держит старую копию страницы). Прежнее объяснение мерцания размытием (`backdrop-filter`) в v136 было неверным: размытие у затемнения и окон уже отключено правилом с `!important`.
- 2026-11-01 — Окна над клавиатурой (v138): закреплённое под вложенным окно опускается вниз само через translate (а не стоит на месте), окно следует за высотой клавиатуры в обе стороны (буквы ↔ цифры) с задержкой 70 мс на «мигания», самописец (три пальца) пишет состояние затемнения и окна. — Окно, привязанное к нижнему краю, зависит от высоты webview, которую Telegram меняет при закрытии клавиатуры; окно, закреплённое по верхнему краю и движимое translate, от неё не зависит. Мерцание фона в Chromium не воспроизводится, поэтому самописец теперь различает «элемент пропал» (opacity/класс) и «не отрисован» (значения не менялись).
- 2026-11-01 — Окна и клавиатура переписаны заново (v139) по покадровому разбору записи эталонного приложения: открытие шторки 246 мс cubic-bezier(0,0,.17,1), закрытие 192 мс cubic-bezier(.58,-.03,1,.5), затемнение 249/198 мс, клавиатура вверх 296 мс и вниз 232 мс; окно привязано к постоянной высоте экрана (`--baseh`), подъём над клавиатурой — одна переменная `--lift`, которую по времени (а не по замерам) ведёт скрипт, запоминая высоту клавиатуры отдельно для цифр, букв и выбора. Удалены прежний скрипт «окна и клавиатура» (пружина, `kbOpen`, закрепление `pin`) и блоки CSS v123/v132/v137. — Прежняя схема двигала окно по замерам высоты webview, которые приходят скачком и с задержкой, и каждый раз пересчитывала положение от нижнего края; эталон жёстко ведёт шторку за клавиатурой по фиксированным кривым. Не воспроизведено: выпадающий список Material (в приложении категория — шторка), мгновенный скачок эталона при смене клавиатуры цифры/буквы заменён подгонкой за 140 мс по просьбе.
- 2026-11-01 — v140: на время окон фон (страница) отключается — затемнение непрозрачное, страница скрыта (`html.bgoff`); у каждого окна свой подъём над клавиатурой, задние окна не реагируют на клавиатуру переднего; у полей «Заметка» и «Теги» отключены подсказки (`autocorrect=off`, `spellcheck=false`). — По записи с телефона (v139) при смене клавиатуры цифры ↔ текст сдвигается всё содержимое webview (и окно, и фон) на высоту строки подсказок и ~170 мс возвращается — это делает iOS/Telegram при изменении высоты клавиатуры, из JS это не остановить. Без строки подсказок буквенная и цифровая клавиатуры, предположительно, одной высоты, и сдвигу неоткуда взяться (проверить на iPhone); скрытый фон убирает заметную часть рывка в любом случае.
- 2026-11-01 — v141: затемнение снова полупрозрачное (список за окном виден), страница под окном только не принимает касаний; постоянная высота экрана (`--baseh`) берётся текущей всегда, когда поле не в фокусе, и обновляется при открытии окна. — По просьбе вернуть затемнение вместо тёмного фона. Ошибка «окно не открылось, только тёмный фон»: Telegram меняет высоту Mini App и без клавиатуры (свернуть/развернуть, смахивание), код принимал это за клавиатуру и не обновлял высоту экрана — окно открывалось ниже видимой части (на стенде при высоте 500 px низ окна был на 652).
- 2026-11-01 — v143: в окне операции внизу кнопки «Удалить» (слева) и «Сохранить» (справа); изменения сохраняются только кнопкой «Сохранить» или Enter, касание мимо окна, Escape и закрытие — без сохранения. — По просьбе: раньше окно сохраняло правки при касании мимо него, и случайное касание записывало незаконченные изменения. Enter в поле тегов с набранным текстом по-прежнему добавляет тег, в пустом — сохраняет.
- 2026-11-01 — v144: шаблоны операций (`cfg.tpls`: тип, сумма, название, категория, теги, `src` — операция-источник) и повтор из окна операции. В окне операции строка «В шаблоны» / «Повторять»; окна шаблона и повтора с кнопками «Отменить» / «Сохранить»; в окне добавления под строкой ввода список «Шаблоны:», нажатие кладёт операцию на проверку, «Добавить» записывает. Повтор, созданный из операции, начинается с её даты, и она считается первой записью. — По просьбе. Шаблон кладётся на проверку, а не записывается сразу, чтобы случайное нажатие ничего не добавило. Заодно исправлено: в форме повтора скрытые поля («День недели», «Месяц») были видны из-за `display:block!important` у полей окна.
- 2026-11-01 — Формат ответов: во время работы — короткие строки о текущем шаге, в конце — краткий итог (что сделано, что добавлено, проблемы и их причины), без объяснений. — Просьба владельца; правило «объясняй архитектуру» в CLAUDE.md заменено.
- 2026-11-01 — v145: окна не прокручиваются вбок (`overflow-x:hidden`, `touch-action:pan-y`); выпадающий список и дата не поднимают окно (клавиатуры у них нет), поднятое окно опускается; высота окна меняется вместе с подъёмом каждый кадр, без CSS-перехода. — По записи с телефона: содержимое окна операции сдвигалось пальцем вбок (пружинящая горизонтальная прокрутка iOS); при выборе в списке окно повтора оставалось поднятым ~1 с; при фокусе верх окна уходил за экран, потому что высота догоняла подъём с переходом 0,32 с.
