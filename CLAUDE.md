# FinansePro — инструкции для Claude

Учёт доходов и расходов в Telegram: Mini App + бот («кофе 300» → запись).
Подробности по темам (история решений, долги/цели, валюты, фокус и клавиатура iOS, прокрутка) — `docs/claude-details.md`: читать нужный раздел, когда работа касается темы. Журнал решений — `DECISIONS.md`.

## Файлы

- `index.html` (~830 КБ) — всё приложение. Читать только поиском (grep по имени функции/строке), не целиком.
- `sw.js`, `manifest.webmanifest`, `icons/`, `mail.html` (мост для письма; почта зашита и тут, и в `SUPPORT.email`), `_headers` (CSP, действует на Cloudflare).
- `worker/` — бот (Cloudflare Workers): webhook, голос → Groq Whisper, очередь фраз, `/api/pending`, `/api/ack`. Данных не хранит; разбор фраз и все данные — в `index.html` (CloudStorage Telegram + localStorage).
- `tools/pagesworker.py` — сборка сайта для выкладки; `tools/codebackup.sh` — копии кода; `tools/diffpage.py` — страница изменений.

## Правила работы

- Русский, прямо, без похвалы. Не соглашаться автоматически: слабую идею — сказать прямо и предложить лучше.
- **Ответы короткие**, как конспект: шаги с номерами, **жирным** главное, 👤/🤖 — кто что делает, «Что дальше» в конце. Без разборов и без базовых инструкций («закройте и откройте приложение, проверьте версию») — только если спросят. Во время работы — 1 фраза, что делаю.
- **Простая правка** (текст, цвет, отступ, пункт «Что нового», мелкая настройка): сделать, проверить, **выложить без вопроса**.
- **Серьёзная правка** (логика, данные, API, заметные анимации, большой код, риск задеть остальное): сначала **план и подтверждение**; выкладка — по слову пользователя.
- **Проверки по размеру правки:** простая — 1–2 нужных теста (или скриншот); полный прогон и замеры — только для серьёзных. В выводе тестов смотреть итог (OK/FAIL, ошибки), не весь лог.
- После правок: `IB_VER` +1 (формат `v`+число, при каждой правке `index.html`), коммит, `codebackup.sh save`, файлом в чат — `index.html`. Важное решение → строка в `DECISIONS.md` (дата — решение — причина).

## Окно «Что нового»

`const WN=[...]` — **только один, последний выпуск**: новый заменяет старый, `id` новый (по нему показывается один раз, `cfg.wnSeen`). Пункты `['эмодзи','Заголовок','1–2 строки простым языком']`; новый выпуск — когда скажет пользователь. Эмодзи с текстом внутри (📅 → «July») не брать. Анимация: `.wnx`, `--i`, `--n` (v205).

## Важное в index.html

- `IB_VER`, `APP_VER` — 5–6-я строка; `IB_VER` держать в первых ~4 КБ (проверка версии читает только начало).
- Суммы — только `fmtN`/`fmt`. Список месяца строится целиком; дни с `content-visibility:auto` (класс `cv`). Смена месяца — `swapAnim` на `el.animate` (не `pxAnim`).
- Прокрутка страницы — только `pgY()`/`pgTo()` (пока открыто окно, прокручивает `body`, `html.wlk`). Смена страницы/раздела: `pgSave()` до, `pgApply()` после `render()`.
- Поля в окнах: фокус ставит iOS сама — не перехватывать касания и не переводить фокус программно; каждое текстовое поле — внутри `label`; программный фокус — `focus({preventScroll:true})`.
- Категории: `CAT2` (старые пользователи, `cfg.catV===2`) / `CAT3` (новые), выбор — `catSet()`; не менять набор существующим.
- Долги и цели связаны с операциями (`t.lk`, `lkSync` в `save()` — источник правды операции; журналы `d.log`/`d.ol`/`g.log` с `id`, `jDel`/`jEdit`, `dgMerge`). Цели не трогать по образцу долгов без просьбы. Подробно — `docs/claude-details.md`.
- Облако (v206): без общей основы (`CL.sb`) облако не затирать — пустое устройство берёт облако целиком (`cloudPull(m,true)`), иначе `cloudMerge`. Спасение после переезда до 21.11.2026: метка `{rescue:1}` в `meta`, `finapp.rsq`/`finapp.rsqd`, `rsqMerge`; после этой даты блок можно убрать. Симуляция облака: `rescue.js`/`sync2.js` в scratchpad (имитация `Telegram.WebApp.CloudStorage`).
- Валюты: шаги v195–v197 сделаны (`cfg.rh`, строка суммы с валютой в окне операции); большая переделка отложена — план в `docs/claude-details.md`.
