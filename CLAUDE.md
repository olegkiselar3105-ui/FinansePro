# FinansePro — инструкции для Claude

## Что за проект

Учёт доходов и расходов в Telegram: Mini App (веб-приложение внутри Telegram) + бот.
Пользователь пишет или наговаривает боту «кофе 300», приложение превращает это в запись.

## Структура

| Путь | Что это | Где работает |
|---|---|---|
| `index.html` | Всё приложение: интерфейс, разбор фраз, хранение, синхронизация с ботом | GitHub Pages (из корня) |
| `sw.js`, `manifest.webmanifest`, `icons/` | Офлайн-режим и установка как приложение | GitHub Pages |
| `_headers` | Заголовки безопасности (CSP). GitHub Pages этот файл игнорирует, он для Cloudflare Pages/Netlify | — |
| `worker/worker.js` | Бот: webhook Telegram, расшифровка голоса (Groq Whisper), очередь сообщений, API для приложения | Cloudflare Workers |
| `worker/wrangler.toml` | Настройки деплоя воркера: имя, compatibility_date, привязки KV/D1 | Cloudflare Workers Builds |
| `worker/.dev.vars.example` | Образец переменных для локального запуска, без значений | — |
| `README.md`, `README.txt` | Краткое и подробное описание | — |
| `DECISIONS.md` | Журнал решений | — |

Приложение лежит в корне, потому что GitHub Pages раздаёт сайт из корня, а адрес Mini App
прописан в BotFather. Не переносить файлы приложения в подпапку.

Адрес приложения (BotFather и `APP_URL`): `https://olegkiselar3105-ui.github.io/FinansePro/` — без метки `?v=`.
Не советовать добавлять `?v=N` в адрес: метка вызывала двойной запуск из-за старой копии страницы в кэше Telegram.
Обновления приложение подхватывает само по `IB_VER`.

## Поток данных

1. Пользователь → бот в Telegram. Telegram шлёт обновление на воркер `POST /webhook`
   (проверяется заголовок `X-Telegram-Bot-Api-Secret-Token` = `WEBHOOK_SECRET`).
2. Воркер: голос → Groq Whisper → текст. Текст кладётся в очередь пользователя:
   D1 (`env.DB`, мгновенно) или, если D1 не привязана, KV (`env.FIN`/`env.INBOX`, с задержкой).
   Бот отвечает «в очереди». Есть дневной лимит на пользователя (`DAILY_LIMIT`).
3. Открытый Mini App опрашивает `GET /api/pending` (адрес воркера — `BOT_URL` в `index.html`).
   Авторизация: приложение передаёт `initData` Telegram, воркер проверяет подпись токеном бота.
4. Приложение само разбирает фразу и сохраняет запись: Telegram CloudStorage + localStorage.
   Воркер записи не разбирает и не хранит финансовые данные — только очередь сырых фраз (до 30 дней).
5. Приложение шлёт `POST /api/ack` (какие id приняты, какие не разобраны, что сделано) →
   бот меняет своё сообщение на «✅ Записано: …».

Следствие: логика разбора фраз и все данные — в `index.html`; воркер — транспорт и голос.

## Секреты и переменные

Хранятся только в Cloudflare: Workers → finansepro → Settings → Variables and Secrets.

- Секреты: `BOT_TOKEN`, `GROQ_KEY`, `WEBHOOK_SECRET`.
- Переменные: `ALLOWED_IDS` (пусто = бот открыт для всех), `DAILY_LIMIT` (по умолчанию 60), `APP_URL`.
- Привязки: KV `FIN` (или `INBOX`), D1 `DB`.

Репозиторий публичный. Токены, ключи, секреты и личные id пользователей в код и коммиты не писать.
id привязок KV/D1 в `worker/wrangler.toml` допустимы: это не секреты, без них не работает автодеплой.
Для локального запуска — `worker/.dev.vars` (в `.gitignore`), образец — `worker/.dev.vars.example`.
`BOT_URL` в `index.html` — публичный адрес воркера, это не секрет.

## Как обновлять

Приложение:
- правки в `index.html` / `sw.js` → коммит в `main` → GitHub Pages обновится сам за 1–2 минуты;
- при каждой правке `index.html` поднимать `IB_VER` (формат `v`+число) — по нему приложение
  замечает новую версию и перезапускается; `APP_VER` — видимая версия, менять по смыслу;
- `sw.js` берёт версию кэша из `IB_VER`, отдельно её не трогать.

Воркер (автоматически, Cloudflare Workers Builds):
- слияние в `main` → Builds собирает `worker/` и выполняет `wrangler deploy`;
- код в панели вручную не править — следующий деплой его перезапишет;
- привязки (KV, D1) объявлять в `wrangler.toml`: привязки, которых нет в файле, при деплое удаляются;
- секреты и переменные живут в панели; `keep_vars = true` не убирать, иначе деплой сотрёт переменные.

Если меняется формат API между приложением и воркером (`/api/pending`, `/api/ack`) — изменения
должны быть обратно совместимы: приложение и воркер обновляются в разное время.

## Правила работы со мной

- Отвечай на русском, прямо и кратко, без похвалы.
- Во время работы — только короткие строки, что делаешь сейчас, без объяснений.
- В конце — кратко: что сделано и что добавлено; если были проблемы — какие и из-за чего. Без разборов и пояснений, пока не спрошу.
- Не соглашайся автоматически: если идея слабая или противоречивая — скажи прямо и предложи лучше.
- Перед изменениями давай план и жди подтверждения, если изменение затрагивает логику, данные или API.
- Никогда не добавляй токены и ключи в код — репозиторий публичный.
- После важного решения добавляй запись в `DECISIONS.md` (формат: дата — решение — причина).
- `index.html` большой (~650 КБ): читай нужные участки поиском (grep по имени функции/строке), а не целиком.

## Полезные места в index.html

- `IB_VER`, `APP_VER`, `BOT_URL` — рядом друг с другом (искать `const IB_VER`).
- `ibCall`, `ibBase` — обращения к воркеру.
- `CloudStorage` — синхронизация данных через облако Telegram.
